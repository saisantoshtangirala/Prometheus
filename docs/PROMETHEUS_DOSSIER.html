Headline finding

Across three independent methods — a spiking network at n=26,210, a genetic search over 1,050 candidates, and a direct information audit of 104 feature/target pairs — no directional signal survives correction for multiple testing. Out-of-sample performance is statistically indistinguishable from zero (t = −0.35, p = 0.735).

The volatility and regime targets do carry real, corrected signal. Seven pairs survive FDR at α = 0.05. That is the one positive result in the project, and it is not directional.

01Architecture

Two machines, three model stacks, one shared genome definition. The split is training on ephemeral GPU, execution on a persistent CPU box.

RunPod · ephemeral
Nightly training
Provisioned per run via REST API, terminated unconditionally. Runs the GA or the SNN pipeline, writes a checkpoint, ships it over scp. Zero idle billing by design.
Hetzner · persistent
Daily execution
8 GB / 2 vCPU. Runs the orchestrator state machine, paper trader, risk guard and Telegram notifier under systemd with Restart=always.

The three model stacks

These are not interchangeable, and conflating them caused the project's original headline bug — a backtest that measured a different model from the one that traded.

02Data layer

Four sources, all free, all fetched directly from the exchange rather than through a scraped intermediary.

Prices — UDiFF bhavcopy

Official NSE daily bhavcopy at archives.nseindia.com/content/cm/BhavCopy_NSE_CM_0_0_0_{YYYYMMDD}_F_0000.csv.zip. One file per session containing every listed security, which makes universe expansion nearly free — going from 10 to 50 names costs no extra network.

Transport behaviour

The archive answers HTTP 403 under load, not 404, and does so intermittently — measured: the same URL returned 403 five times then OK 955 on the sixth attempt. Collapsing every failure to None converted throttling into phantom holidays and silently lost ~20% of sessions.

Corporate actions — and why they are a correctness prerequisite

Raw bhavcopy closes are unadjusted. The first implementation assumed PrvsClsgPric was the exchange's adjusted previous close. It is not:

Measured falsification 
RELIANCE, 1:1 bonus, ex-date 2024-10-28
  PrvsClsgPric = 2655.70    ClsPric = 1334.35    →  −49.76%

That fake crash slipped under a ±50% "data error" clamp — a sanity filter tuned to a round number misses the most common corporate action there is. It produced 49.9% annualised volatility for RELIANCE against ~20% for its peers, and a −53.8% total return the stock never had.

Adjustment is applied on the ex-date to the return, not by back-adjusting a price series:

Ex-date adjustment 
bonus a:b     adj_prev = prev × b/(a+b)
split X→Y     adj_prev = prev × Y/X
dividend D    adj_close = close + D
demerger      NOT COMPUTABLE → masked

Demergers are masked, never guessed: the value transferred to the resulting entity is not in the feed. ITC's demerger prints −8.09%, which looks like an ordinary bad day and is not one — a holder lost nothing. Any residual move beyond ±25% after adjustment is also masked and counted.

Effect of correct adjustment · RELIANCE

Annualised volatility 49.9% → 21.5%. Total return −53.8% → −6.6%. Peer group now 18–27%, a realistic NSE large-cap profile.

Institutional flows — NSCCL participant archive

The endpoint everyone recommends, api/fiidiiTradeReact, is useless for research: it ignores its date parameters. ?date= and ?from=&to= both return byte-identical 216-byte payloads containing only the latest session. There is no history behind it.

The NSCCL archive fao_participant_vol_{DDMMYYYY}.csv is date-addressable and verified back to 2019-04-01. It gives long/short contract counts by Client / DII / FII / Pro across index futures, stock futures and options.

Net positioning ratio 
net(p) = (Long(p) − Short(p)) / (Long(p) + Short(p))     ∈ [−1, 1]

fii_opt_directional = net( CallLong + PutShort ,  PutLong + CallShort )

Positioning, not flow — a stock rather than a difference, so it needs no baseline to interpret. Long calls and short puts are both bullish expressions; netting them gives one signed exposure.

Publish lag

The report for session T is published after the close on T. align_flow_features therefore raises on lag_bars < 1 rather than warning. Order of operations is deliberate: reindex to the price calendar → forward-fill → shift by lag in trading bars → causal z-score → tanh squash.

03Feature engineering

26 channels: 20 technical indicators computed per asset, plus 6 market-wide flow channels broadcast across the cross-section.

Two non-negotiables

  1. Every indicator is causal. Row t uses bars ≤ t and predicts bar t+1. .rolling() includes the current row, which is correct only because the signal at t is applied to the return from t to t+1.
  2. Normalisation is per-asset and causal. Expanding-window z-score, never full-sample — a full-sample z-score leaks the future into every row and is the single most common silent look-ahead in technical backtests.
Channel normalisation 
μ_t = expanding_mean(x, min_periods=20)
σ_t = expanding_std(x,  min_periods=20)

z_t      = (x_t − μ_t) / σ_t
channel  = tanh(z_t / 2)                      ∈ ≈[−1, 1]

The tanh squash puts every channel on the fixed scale the genome's entry/exit thresholds are defined against. Scale mismatch between a threshold and the quantity it gates has caused two separate bugs in this project.

04Prediction targets

Four targets from one price history. The contract: target[t] depends only on bars strictly after t; features[t] only on bars ≤ t.

Target definitions · horizon h = 5 
direction_1d     r_{t→t+1}                              signed, not autocorrelated
rel_strength_1d  r_{t→t+1} − mean_assets(r_{t→t+1})     market factor removed
vol_5d           std(r_{t+1..t+h}, ddof=1)              autocorrelated — cheap
regime_shift_5d  log( vol_fwd(h) / vol_trail(h) )       level removed
Warning that must travel with every vol result

Predicting volatility is not the same as making money. Realised vol is strongly autocorrelated, so any vol-ish feature scores well against a vol target — that is why GARCH works, and it is nearly free information. Converting a vol forecast into P&L needs an instrument whose price is a function of vol (options — not traded here) or a sizing rule whose edge comes from elsewhere.

Persistence baseline

Every target is scored against the trivial "tomorrow looks like today" forecast, and only the incremental dependence counts.

Baselines, and one correction 
vol_5d           baseline = std(r_{t−h+1..t})            trailing realised vol
regime_shift_5d  baseline = log( vol_trail(h) )          ← CORRECTED
directional      baseline = r_{t−1→t}                    yesterday's return

The regime baseline originally used a ratio of two past windows. That does not remove the mechanical term: regime_shift = log(fwd_vol) − log(trail_vol) carries trailing vol in its denominator, and atr_pct is trailing vol. On a pure random walk the audit reported incremental ρ = −0.3864 at q = 0.04 — a significant finding on structureless data. Controlling for log(trail_vol) itself removes exactly the mechanical component; the sign then flipped to +0.1485, revealing a real positive the artefact had masked.

05Information audit

Measure whether information exists before letting an optimiser search for it. This is the step every earlier cycle in the project was missing.

A search over 1,050 candidates returns a strong in-sample number whether or not the data contains anything. The audit inverts the order: no optimisation at all, just the dependence between each feature and each target, with four controls.

ControlFailure it prevents
Block permutation
21-bar blocks		Features and targets are both autocorrelated. An iid shuffle destroys that structure and produces a null far narrower than reality, so ordinary p-values come out spuriously tiny.
Rows permuted jointly across assetsTen NSE large-caps on one day are not ten independent observations — they share a market factor.
Benjamini–Hochberg FDR
over all 104 pairs		At α = 0.05, ~5 of 104 look significant by chance alone. Reporting the best without correction is the multiple-testing error in a different costume.
Persistence partialled outVol predicting vol is nearly free; only the residual counts.
Statistic and null 
ρ        = Spearman rank correlation, pooled over (t, asset)
ρ_incr   = corr( rank(x),  resid( rank(y) ~ rank(baseline) ) )

null     block-permute target rows jointly:
           cut into ⌈n/21⌉ contiguous blocks, shuffle blocks, truncate

p        = (#{ |ρ_perm| ≥ |ρ_obs| } + 1) / (n_perm + 1)

BH:      sort p ascending; q_(i) = min over j≥i of  p_(j) · n / j
         reject where q ≤ α

The +1 in numerator and denominator matters: a permutation p-value is an estimate and can never legitimately be 0. Spearman needs no linearity assumption and is robust to the fat tails that make Pearson unstable on returns.

Market-wide feature correction

Flow features are one number per session broadcast across 10 assets. Pooled as T×A they claim 5,870 observations from ~588 independent days, and the rank transform breaks the cancellation a demeaned target should give a market-wide predictor.

Control experiment

Six pure-noise market-wide features run through the pooled path reached |ρ_incr| up to 0.0126 on rel_strength_1d and produced 2–3 spurious FDR survivors per seed. The real fii_stk_fut_net scored 0.0167 — the same order of magnitude.

Asset-invariant channels are now detected automatically and scored against the cross-sectional mean of the target, at their true sample size of n_rows. fii_stk_fut_net → rel_strength_1d went from "survives FDR, q = 0.039" to p = 0.60. It was an artefact.

Calibration

Two-sided. On a random walk with real indicators the audit must find nothing — that configuration is what caught the regime artefact, which a random-feature null could not. On planted signal it must fire: a synthetic predictor at ρ = 0.25 was recovered at ρ = 0.23, flagging the correct channel and none of seven decoys.

Signal construction 
vote_i = +1   if  channel_i >  entry_i
         −1   if  channel_i < −exit_i
          0   otherwise

score  = Σ w_i · vote_i        (weights already sum to 1)   ∈ [−1, 1]

long_only:  score ← max(score, 0)     ← suppress, do not clip

Suppressing the score rather than clipping the position is deliberate: a bearish signal should mean "do not hold", not "hold a smaller long". Long-only is the default because NSE cash under CNC does not permit carrying a short overnight — the simulator previously held them for up to 90 days, making roughly half the measured opportunity set unimplementable.

Fitness — redefined

The original objective was Sharpe × (1 − MaxDD) × (WinRate / 0.5) with a minimum-win-rate gate. Both win-rate terms are gone.

Current objective 
fitness = Sharpe_net × (1 − MaxDD) × n/(n + 20)

  × PENALTY_MULTIPLIER (0.1)   if MaxDD > 0.20
  = ABSTENTION_FITNESS (−0.05) if n_trades == 0

Three reasons the win-rate term was removed, all measured. (1) Break-even win rate at a 1-day hold after 22bp is 61.1%, so multiplying by WinRate/0.5 optimised hard for a number that loses money at the value being targeted. (2) It scored a 45%-hit-rate/2:1 strategy at 0.90× against a 60%/1:1 loser at 1.20× — Sharpe already prices asymmetry correctly. (3) Evidence shrinkage n/(n+20) replaces it: the measured artefact was an out-of-sample Sharpe of +1.18 on three trades, which a naive report called a 66.7% win rate. Three trades now keep 13% of their score; 100 keep 83%.

Why abstention is −0.05 and not 0.0

Zero beat every negative score, making never-trading the global optimum the moment a search started failing. Measured: 3 of 8 seeds abstained, and their 0.00s pulled an arm's mean from −1.45 up to −0.90 — making the worse arm look better. A small negative keeps abstention better than losing (which is economically correct) without letting it dominate, and BacktestStats.abstained keeps it out of any average as a zero.

Volatility targeting

Position sizing 
σ̂_t   = std(r_{t−19..t}, ddof=1) × √252          20-bar trailing, causal

scale = clip( vol_target / σ̂_t , 0, 3.0 )         cap is load-bearing
size  = clip( |score| · kelly_fraction · scale , 0, max_position )

The 3× cap matters: an unclamped target/estimate ratio diverges as the estimate goes to zero, which is exactly what a halted or stale name produces. This is the one place the audit's positive result is used — and it does not create directional edge. It stabilises risk per unit of exposure, which raises Sharpe for whatever signal exists, including a zero one.

Exit conditions

A position closes on the first of: trailing stop breach, hold_days expiry, or a vote flip against the open position exceeding conviction_floor. The trailing stop is genuinely path-dependent, which is why simulate() loops over time rather than vectorising — replacing it with a vectorised approximation would mean the backtest measures a different strategy from the one that trades.

07Statistical controls

The machinery that distinguishes a skill estimate from the maximum of a large search.

Expected maximum Sharpe of N worthless strategies 
γ = 0.5772156649                                    Euler–Mascheroni

E[max Z_N] = z₁·(1 − γ) + z₂·γ
  where  z₁ = Φ⁻¹(1 − 1/N)
         z₂ = Φ⁻¹(1 − 1/(N·e))

SR_benchmark = E[max Z_N] · √(252 / n_obs)

Grows like √(2 ln N). On a 252-bar window the standard error of an annualised Sharpe is roughly 1.0, so searching 1,000 random strategies over one year is expected to surface an in-sample Sharpe near 3 even if every candidate is worthless.

Deflated Sharpe probability · Bailey & López de Prado 
sr        = SR_observed / √252                       de-annualise per bar
sr_bench  = E[max Z_N] / √(n − 1)

              ⎛        sr − sr_bench           ⎞
DSR = Φ ⎜ ───────────────────────────── ⎟
              ⎝ √( (1 − γ₃·sr + (γ₄−1)/4·sr²) / (n−1) ) ⎠

gate:  DSR ≥ 0.95

γ₃ = skew, γ₄ = kurtosis of the return series. n_trials is the real search budget — population × (generations + 1) — not a token 3. Under-reporting it is how a search result gets mistaken for a skill estimate.

Required validation window 
W ≥ ⌈ min_trades × max_hold / (n_assets × duty_cycle) ⌉

  min_trades = 20      duty_cycle = 0.25   ← MEASURED, not assumed

A strategy holding h days completes roughly W/h rounds per asset. The duty-cycle term corrects for conviction_floor gating most entries — without it the formula is optimistic by ~4×: its own first version returned 180 bars claiming ≥20 trades, and the run delivered 9. At the measured duty cycle, validating a 90-day hold on 10 assets needs ~720 validation bars — more history than the UDiFF archive holds. The cheap fix is more assets, not more history.

Directional accuracy ↔ correlation 
For bivariate normal:   P(sign match) = ½ + arcsin(ρ)/π

08Cost arithmetic

The calculation that reframes the whole project: 55% accuracy was simultaneously unreachable on this data and unprofitable if reached.

The gap

A 55% win rate at a 1-day hold loses 12.1 bp per round trip, because break-even is 61.1%. Reaching it needs ρ = 0.156 against forward returns; the best directional feature measured ρ = 0.035 and did not survive correction. That is a shortfall of 4.4× on a target that would lose money anyway.

Hence the hold floor moved 2 → 5 days and the ceiling 60 → 90: one-day trading here is not a hard problem, it is an arithmetically closed one, and leaving it in the search space only lets the GA find noise there.

09Execution layer

Signal → target weight → fill, with slippage, market impact, and a cash constraint. Exercised by 38 tests, not inspected.

Fill mechanics 
effective_cap  = min(kelly_cap, kelly_cap · position_cap)     longs only
target_weight  = clip(target_weight, −effective_cap, +effective_cap)
target_shares  = target_weight · equity / price
δ              = target_shares − held
                 skip if |δ · price| < 1.0                    sub-dollar

slip      = base(liquidity tier) + trade_value/ADV × 0.01      cap 5%
fill      = price · (1 + slip)   buy
            price · (1 − slip)   sell

cash      −= δ · fill + commission                             scaled to available
Kelly sizing · prometheus/loss/kelly_optimizer.py 
p_adj = ½ + (p_win − ½) · confidence
q     = 1 − p_adj
b     = avg_win / avg_loss

f*    = (b · p_adj − q) / b

f     = clip( f* · kelly_fraction · neuromod_multiplier , ±max_position )

Confidence shrinks the win probability toward a coin flip, so a low-confidence prediction sizes small regardless of its point estimate. The neuromodulation multiplier is the cortisol channel described in §10.

Verified by execution, not reading

Slippage is directional (buys fill above, sells below). Market impact caps at 5%. Cash never overdraws under a greedy multi-position buy. A bankrupt price writes off instead of dividing by zero. The panic gate blocks new longs. SQLite survived 6 concurrent writers — 150 rows, no corruption, no deadlock — plus a concurrent reader.

One bounded imperfection: the position cap is applied to pre-trade equity, and slippage then lowers equity, so the measured post-fill position sits at 0.25003 against a 0.25 cap — a 0.012% overshoot bounded by the slippage rate. Documented and asserted rather than silently tolerated.

10Risk & fear systems

Two independent defensive layers, plus a literal amygdala model. Their costs differ by an order of magnitude.

RiskGuard — deterministic, file-backed

Automatic checks, in priority order 
kill switch     KILL_SWITCH file present            → immediate
daily loss      (day_start − equity) / day_start  ≥ max_daily_loss_pct   0.05
drawdown        (peak − equity) / peak            ≥ max_drawdown_pct     0.20

Limits are fractions, not percentages — 0.05 means 5%. Halt state lives in a file, so a restart cannot clear it; clearing an automatic halt is a deliberate operator action. check() reports but does not itself trip — the orchestrator decides — and trip() is idempotent so a second breach never overwrites the original cause. _equity_history is seeded with opening capital at construction, so the guard is live on day 1 before any close has run.

CortisolSystem — the amygdala model

Cortisol rises with market entropy, drawdown, correlation breakdown and causal-confidence collapse. The response is deliberately asymmetric: spikes fast, recovers slowly.

Constants 
FEAR_POSITION_CAP = 0.30      hard-wired 70% position reduction in fear mode
fear_threshold    = 0.7       CORT level triggering full defensive mode
lockout_duration  = 30        bars held in fear after a flash crash
fast_decay 0.95 / slow_decay 0.98      asymmetric rise vs recovery

rule_stress = 0.5·entropy + 0.3·drawdown + 0.2·corr_breakdown
stress      = max(neural_stress, rule_stress)       ← hard floor bypasses the net

Per-asset fear states exist so one ticker's crash does not paralyse the whole book.

The distinction that matters

Fear that changes when you trade destroys efficiency. Fear that changes how much you trade does not.

Tightening the trailing stop from off to 2% costs 2.38 pp of return and 0.51 Sharpe to buy 0.13 pp of drawdown protection — roughly an 18:1 bad trade. The mechanism is turnover and the arithmetic closes: daily turnover rises 0.0030 → 0.0045, which over 588 bars is 0.88 extra turnover units × 22 bp ≈ 1.94 pp of the 2.38 pp gap.

The cortisol 70% cut is Sharpe-neutral: +1.53 either way. It scales return and risk proportionally — that is deleveraging, not inefficiency. Given a 2–20% stop range the GA independently evolved 15.8%, near the top: it discovered unaided that flinching is expensive.

Two bugs the chaos work surfaced

Lorenz convergence. The reservoir converged rather than diverged (early 2.56e-04 → late 1.10e-04). Real dynamical cause: transverse Lyapunov exponents (≈ −14.6) dominate the positive one (≈ +0.9) off-attractor. Fixed with a 50-step burn-in and dt 0.01 → 0.02; measured λ_max moved +0.38 → +0.82.

Deadband collapse. Raw signals ≈0.17 against a threshold sampled in [0, 0.9]; tanh(0.17 × 0.70) = 0.119 fell under the deadband, zeroing every position. MAP-Elites then selected for it — never-trading scores exactly 0.0 against negative after costs — and the archive's best fitness was literally 0.0000. The same class as the SNN size_scale bug. Fixed by normalising to train-set signal std.

A conclusion that did not replicate

The 10-name runs reported 8/8 seeds with profit factor below 1.0, sign test p = 0.0078, and the finding was stated as "the strategies reliably lose money out of sample." It does not replicate. With an adequately powered window it is 4/8, p = 1.000.

The difference is trade count: 9 per seed versus 42. Nine trades with 22 bp on each cannot distinguish losing from trading badly. The corrected statement is weaker and duller — performance is indistinguishable from zero. 14Limitations

What this system does not know, cannot currently measure, or has not been tested against.

Data

  • History depth. The UDiFF bhavcopy archive begins in 2024 — about 650 sessions. Validating a 90-day hold on 10 assets needs ~720 validation bars plus training. The history is not there; universe width is the substitute.
  • Survivorship. top_liquid_symbols selects point-in-time by turnover, which removes the "chose the list after seeing the outcome" component. Names that later delisted still vanish from the panel.
  • Order flow. Cannot be backfilled from Kite at any price. The recorder must accumulate it forward; every unrecorded day is permanently gone.
  • Ad-hoc holidays. NSE occasionally adds one by late circular. No calendar published in advance can capture it.

Measurement

  • Float determinism across machines is unverified. The checkpoint is JSON floats, so serialisation is safe — but ewm/rolling numerics can differ across pandas versions, and pandas is pinned only as >=2.0.0. RunPod and Hetzner could compute different indicators from identical inputs.
  • Backtest figures predate the long-only fix. Every result in §12 was measured with overnight shorts enabled. The conclusion will not reverse, but the specific numbers need re-running to be quotable.
  • No slippage model in the GA simulator — only a flat 22 bp on turnover. The live paper trader does model slippage and impact.

Untested paths

  • Partial checkpoint corruption after a mid-training crash
  • RunPod API outage or rate limit
  • Orchestrator restart mid-Evolution (resume state exists; the path has been read, not run)
  • Disk-full and OOM on the 8 GB box
  • Signal-to-fill quantity fidelity asserted numerically

The honest position

Every structural defect that could manufacture a false positive has been found and fixed — leakage, multiple testing, abstention scoring, mechanical artefacts, target poisoning, validation-window arithmetic. What remains is a correctly-measured null result on direction, a real but non-directional signal on volatility, and a gate that refuses to trade.

The untested lever is intraday microstructure. It is the one input class that has not been measured, and the only one that cannot be measured retroactively.
